# Code Generation Workflow

## Tools

| Tool | Purpose | Config | Output |
|------|---------|--------|--------|
| `sqlc` | SQL → Go (type-safe queries) | `sqlc.yaml` | `internal/generated/rdb/` |
| `oapi-codegen` | OpenAPI → Go (server/client) | `internal/generated/oapi/rest/generate.go` | `internal/generated/oapi/rest/rest.gen.go` |

Both installed via `make setup` → `dev_tools/bin/`.

## sqlc Configuration (`sqlc.yaml`)

```yaml
version: "2"
sql:
  - engine: "postgresql"
    queries: "sql/postgres/query.sql"
    schema: "sql/postgres/schema/public"
    gen:
      go:
        package: "rdb"
        out: "internal/generated/rdb"
        sql_package: "pgx/v5"
        output_db_file_name: "db_gen.go"
        output_models_file_name: "models_gen.go"
        output_files_suffix: "_gen"
```

**Key choices**:
- `pgx/v5` — native PostgreSQL driver, no `database/sql` overhead.
- `_gen` suffix — distinguishes generated from hand-written.
- Single package `rdb` — all queries + models together (no cyclic deps).

## oapi-codegen Configuration (`generate.go`)

```go
//go:generate go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest \
  -generate types,strict-server,chi-server \
  -package rest \
  -o rest.gen.go \
  rest.yaml
```

**Key choices**:
- `strict-server` — compile-time interface compliance.
- `chi-server` — generates `chi.Router` compatible handlers (though we use `http.ServeMux` wrapper).
- `types` — generates request/response structs.
- **Not generating**: `client` (enabled in `oapi.yaml` but not in generate directive — deliberate).

## Regeneration Commands

```bash
# SQL layer
make sqlc-generate

# API layer
cd internal/generated/oapi/rest && go generate

# Or both
make sqlc-generate && cd internal/generated/oapi/rest && go generate
```

**CI**: Both run in `make ci` → `make lint` (no dedicated generate check; compilation fails if stale).

## Why This Combination?

| Layer | Alternative | Why Chosen |
|-------|-------------|------------|
| DB | GORM, sqlx, ent | sqlc: SQL-first, zero runtime reflection, compile-time safety |
| API | Manual, gRPC, GraphQL | oapi-codegen: OpenAPI standard, HTTP/JSON native, strict server |

**Not gRPC**: External consumers need HTTP/JSON. Internal could use gRPC but adds complexity (protobuf, gateway).

**Not GraphQL**: Overkill for current scope. REST + OpenAPI sufficient.

## Generated Files — Do Not Edit

| File | Regenerated By | Safe to Edit? |
|------|----------------|---------------|
| `internal/generated/rdb/models_gen.go` | `make sqlc-generate` | ❌ |
| `internal/generated/rdb/query.sql_gen.go` | `make sqlc-generate` | ❌ |
| `internal/generated/rdb/db_gen.go` | `make sqlc-generate` | ❌ |
| `internal/generated/oapi/rest/rest.gen.go` | `go generate` | ❌ |

**Extension pattern**: 
- DB: Hand-written repository in `logic/` wraps `*rdb.Queries`.
- API: Hand-written `handler` struct in `logic/rest/` implements generated interface.

## Version Pinning

```makefile
$(DEV_BIN)/sqlc:
	go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest

$(DEV_BIN)/oapi-codegen:  # not in Makefile yet
	go install github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest
```

**Why `@latest` not pinned?**
- `dev_tools/bin/` is local, not committed.
- `make setup` fetches latest — developer controls upgrade.
- CI could pin via `go.toolchain` directive or `go.work` if needed.
