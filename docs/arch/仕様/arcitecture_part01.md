# 1. はじめに

## 1.1 目的

本仕様は、セルフホスト型 IP アドレス管理プラットフォームの要件を定義する。

本システムは、HTTP(S) によってデバイスごとの IPv4 アドレスおよび IPv6 アドレスを登録、更新、参照する機能を提供する。

ルーター、Linux ホスト、またはエージェント等のデバイスは自身のアドレスを通知し、外部システムは ManagementGroup 単位で複数デバイスのアドレスを参照する。

本システムは次の権限分離を重視する。

- 人間による管理操作は `UserSession` で行う。
- デバイスによる更新操作は `DeviceCredential` で行う。
- 機械による読み取り操作は `GroupReadToken` で行う。

---

## 1.2 想定ユースケース

本システムは、少なくとも以下のユースケースを想定する。

### 1.2.1 ルーターのアドレス管理

自宅、拠点、または小規模組織のルーターが自身の現在のアドレスを継続的に登録する。

### 1.2.2 Linux ホストの自己通知

Linux ホストまたは専用エージェントが、自身のアドレス変更をシステムへ通知する。

### 1.2.3 Dual Stack 環境の追跡

IPv4 および IPv6 が共存する環境において、デバイスごとのアドレス状態を管理する。

### 1.2.4 外部システムによる参照

外部システムが ManagementGroup 単位で複数 Device のアドレスを参照する。

### 1.2.5 非同期外部連携

アドレス更新を契機として、外部 API へ非同期通知を行う。

---

## 1.3 非目的

以下は本システムの対象外とする。

### 1.3.1 DNS サーバー機能

本システムは DNS サーバーそのものを提供しない。

### 1.3.2 IP アドレスの所有性検証

本システムは `submitted_ip` の所有性または到達性を検証しない。

### 1.3.3 外部 API の同期実行

外部 API 呼び出しは非同期で実施するものとし、API リクエスト処理中に同期実行してはならない。

### 1.3.4 インフラストラクチャ管理機能

以下は application 層の責務外とする。

- TLS termination
- WAF
- L7 rate limit
- Trusted Proxy Header 管理
- Reverse Proxy 設定
- External Exposure Control
- Reverse Proxy Access Logging

### 1.3.5 バックアップおよび復元

Backup および Restore はインフラ層の責務とする。

ただし application は Backup および Restore を阻害しない設計でなければならない。

---

## 1.4 対象読者

本仕様は以下を対象とする。

- ソフトウェアエンジニア
- インフラエンジニア
- SRE
- 運用担当者
- セキュリティレビュー担当者
- システム監査担当者

---

## 1.5 設計目標

本システムは以下を主要な設計目標とする。

### 1.5.1 セルフホスト運用

単一ユーザー環境から小規模組織まで運用できること。

### 1.5.2 権限分離

人間、デバイス、読み取り専用システムの権限を明確に分離すること。

### 1.5.3 最小権限

各 Credential は最小限の操作権限のみを持つこと。

### 1.5.4 IPv4 / IPv6 両対応

IPv4 および IPv6 を同等に扱うこと。

### 1.5.5 監査可能性

重要な操作は AuditLog および UpdateHistory に記録されること。

### 1.5.6 運用容易性

期限切れデータや履歴データを CleanupJob によって定期管理できること。
